**The mismatch-axis flow check fails, and CI hides it.** The step is `continue-on-error`, so both
the step and the job report success. The failure predates this program: the only library change on
this branch is a header comment. Diagnosis:

| quantity | value |
|---|---|
| `run_mc.py` hardcoded NMOS5V0 threshold coefficient | `DVTH_3SIG_BASE = 0.0135` V·µm |
| wrapper coefficient since `dc7de19` (O5 A_VT widening, 2026-07-24) | 0.033 V·µm (2.44×) |
| measured σ(log I1/I2), N = 400 | 1.014 % |
| intended, as coded | 0.364 % (measured ÷ intended = 2.79×) |
| intended, with the current coefficient | 0.839 % |
| gap remaining after the correction | +21 %, about 6 standard errors at N = 400 — not sampling noise |

The stale coefficient accounts for most of the gap. The remaining +21 % is unexplained. Proposal:
correct the coefficient and diagnose the residual when this check is rebuilt on the driver
(Phase 3's sensitivity mode decomposes σ per term; Phase 5 makes MC checks gating). Until then,
CI's green status for Phase E carries no information.
